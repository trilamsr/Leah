# JARVIS-aesthetic personal-use dashboard

Single-page dashboard at `http://localhost:8080/dashboard` serving Leah's
operator (one human, Tri). Visual identity borrows from Iron Man's JARVIS
HUD — dark background, cyan accents, monospace, subtle ambient motion —
but **deliberately excludes** 3D models, WebGL, holograms, voice
visualizations, and avatar rendering. Those carry weeks of cost for a
surface the operator will open occasionally, not daily.

This spec is **spec-only**. Scaffolding is deferred until the memory
and self-learn layers confirm their data shapes. See §10.

---

## 1. Goal + tone

**Goal**: One glance at `localhost:8080/dashboard` answers "is Leah alive,
what is she doing right now, what did she just decide, am I burning
budget?" in under 3 seconds.

**Tone**: JARVIS-aesthetic *without* the cool factor that costs weeks.
The aesthetic is delivered through:

- Dark near-black background (#0a0e14)
- Cyan accent (#00d4ff) for live data + active state
- Amber (#ffb74d) for warnings, muted red (#ff5252) for failures
- Monospace font everywhere (SF Mono / JetBrains Mono fallback)
- Single subtle pulse animation on the "alive" dot (3s loop, CSS
  `@keyframes`, no JS, paused when tab is hidden)
- Grid layout with thin cyan borders + subtle box-glow

**Non-goals for tone**: 3D rotation, parallax, WebGL shaders, audio
visualizations, animated SVG portrait, glassmorphism beyond a single
1px border treatment.

---

## 2. Premise-stress-test

**Embedded premise**: JARVIS-style holographic UI = high operator delight.

**Strongest case against**: Leah's primary surfaces are voice, terminal,
and push notifications. A dashboard is a *weekly-open* artifact, not a
daily driver. Spending a week on Three.js + WebGL + custom shaders is
misallocation vs. voice work, Memory M2, and self-improvement tier-1.

**Refutation severity**: HIGH against holograms / 3D / shaders. LOW
against a minimal dashboard that takes 1-2 days and reuses the daemon's
existing HTTP-less process by adding a tiny `net/http` listener.

**Survives**: minimal dashboard YES. Holograms NO. This spec is the
minimal-dashboard branch.

| Token       | Value                                |
|-------------|--------------------------------------|
| `--bg`      | `#0a0e14`                            |
| `--bg-2`    | `#10151c` (quadrant panel)           |
| `--fg`      | `#c8d3e0`                            |
| `--accent`  | `#00d4ff` (cyan)                     |
| `--warn`    | `#ffb74d` (amber)                    |
| `--fail`    | `#ff5252` (muted red)                |
| `--ok`      | `#7fdba8` (muted green)              |
| `--border`  | `rgba(0, 212, 255, 0.18)`            |
| `--glow`    | `0 0 8px rgba(0, 212, 255, 0.35)`    |

**Font stack**: `'SF Mono', 'JetBrains Mono', 'Menlo', monospace`.
No web-font download — system stack only (zero network, faster paint).

**Animation rules**:
- Single `pulse` keyframe (3s, ease-in-out, infinite) on `.alive-dot`
- `@media (prefers-reduced-motion: reduce)` disables it
- `document.visibilityState === "hidden"` toggles a `body.paused` class
  that overrides `animation-play-state: paused` (zero CPU on blur)
- No other animation. No transitions on hover beyond 100ms color shift.

## 4. Data sources + API contract

**Single endpoint, polled** (see §6 for why SSE was cut):

```
GET /api/state
```

Returns one JSON blob with everything the dashboard needs. Polled every
**3 seconds** by the client. Server-side cost is bounded — daemon already
holds this state in memory.

```json
{
  "ts": "2026-06-09T14:23:11Z",
  "daemon": {
    "uptime_seconds": 41203,
    "last_tick_at": "2026-06-09T14:23:09Z",
    "alive": true
  },
  "audit_tail": [
    { "ts": "...", "actor": "leah", "action": "...", "subject": "..." }
  ],
  "agents": [
    { "id": "agent-7", "branch": "regatta/agent-7", "state": "running",
      "pr_url": "...", "since": "..." }
  ],
  "memory": {
    "contacts": 12,
    "projects": 4,
    "decisions": 87,
    "recent_decisions": [
      { "ts": "...", "summary": "..." }
    ]
  },
  "ops": {
    "budget_spent_usd": 4.21,
    "budget_ceiling_usd": 25.00,
    "burn_per_day_usd": 1.05,
    "heartbeat_last_pinged_at": "2026-06-09T14:22:51Z"
  }
}
```

Data sources (read-only, no UI-driven writes Phase 1):
- **audit_tail** — tail of `audit.jsonl` (last 20)
- **agents** — `gh pr list --head 'regatta/agent-*'` cached by daemon
- **memory** — `SELECT count(*) FROM contacts/projects/decisions` +
  `SELECT ... ORDER BY ts DESC LIMIT 5` from `memory.db`
- **ops** — daemon's existing budget tracker + healthchecks last-ping
- **daemon** — daemon's process start-time + last regatta poll

**Single-endpoint rationale**: 4-5 endpoints (audit / agents / memory /
ops) bloat the surface, add 4-5 fetch racing conditions on the client,
and complicate error handling. One endpoint, one fetch, one
`renderState(json)` call. Cost: ~2-5 KB per poll. At 3s cadence and a
weekly-open dashboard, server load is negligible.

- The "alive" dot in bottom-right corner pulses cyan; turns amber if
  `daemon.last_tick_at` is >60s old; turns red if >300s old
- No header, no nav, no footer — the dashboard *is* the page

## 6. Tech stack decision

**Pick (a) vanilla HTML + JS + CSS, served by Go from the daemon.**

Rationale (operator priority: UX > ease > perf > best-practice >
speed > velocity):

| Criterion          | Vanilla         | Next.js          | Svelte+Vite      |
|--------------------|-----------------|------------------|------------------|
| Single binary      | YES             | NO               | NO               |
| Node dependency    | NO              | YES              | YES              |
| Build step         | NO              | YES (webpack)    | YES (vite)       |
| Hot-reload         | reload-tab      | yes              | yes              |
| Time-to-first-byte | one Go file     | npm i + build    | npm i + build    |
| Personal-use fit   | excellent       | over-built       | over-built       |

Vanilla wins on every operator-priority axis. One `embed.FS` in Go
serves `dashboard.html`, `dashboard.css`, `dashboard.js`. No build, no
Node, no `package.json`, no node_modules. ~300 LoC total client-side.

## 7. Backend changes needed

The daemon (`cmd/leah-daemon/main.go`) currently has no HTTP server.
Adding one is **mission creep risk** (HIGH) flagged by critic in §11.
Mitigation: add the smallest possible `net/http.Server` in a new
package `internal/web/`, wire from daemon `main`, behind a flag
`--dashboard-addr=localhost:8080` that defaults to **off**.

Files added:
- `internal/web/server.go` (~80 LoC) — `func Serve(ctx, addr, state
  StateProvider) error`
- `internal/web/state.go` (~40 LoC) — `StateProvider interface { Snapshot()
  State }` implemented by the daemon's existing state struct
- `internal/web/assets/dashboard.{html,css,js}` (~300 LoC total)
- `internal/web/assets.go` — `//go:embed assets/*` FS
- `internal/web/server_test.go` — handler returns 200 + valid JSON
  shape; reduced-motion CSS rule present; SSE not present (we cut it)

Files modified:
- `cmd/leah-daemon/main.go` — add `--dashboard-addr` flag, spawn
  `web.Serve` goroutine when flag set, share state struct
- `internal/daemon/state.go` (or equivalent) — expose `Snapshot()`
  method returning the §4 schema

Hard constraints:
- Bind to `127.0.0.1` only (never `0.0.0.0`) — enforced in `web.Serve`
- No middleware, no router framework — `http.ServeMux` is enough
- No log spam — `/api/state` polling logged at DEBUG, not INFO

## 8. Build order (5 tasks max)

1. **Backend state interface** — add `Snapshot()` to daemon state
   returning §4 schema; pure data-shape work, no HTTP. Unit test:
   snapshot serializes to JSON matching schema. TDD: failing test first.
2. **HTTP server skeleton** — `internal/web/server.go` with `/api/state`
   handler + 127.0.0.1 bind enforcement. Test: handler returns 200,
   JSON body shape validates, non-loopback bind rejected.
3. **Embedded assets** — `dashboard.html` + `dashboard.css` + a stub
   `dashboard.js` that fetches `/api/state` and logs to console.
   Smoke: `curl localhost:8080/dashboard` returns HTML.
4. **Client renderer** — `dashboard.js` renders all 4 quadrants from
   `/api/state`. Includes 3s poll, visibility-hidden pause, error
   banner on fetch failure. No tests (DOM render is visual).
5. **Wire daemon flag** — `--dashboard-addr=localhost:8080` opt-in;
   default off so existing daemon behavior unchanged. Integration:
   start daemon with flag, curl endpoint, assert 200 + uptime > 0.

Each task = one PR, file-disjoint, sequenceable by single operator in
one ~4-hour session (after memory + self-learn unblock the schema).

## 9. Cuts (explicit non-goals)

- 3D models, WebGL, shaders, Three.js, holograms — over-scoped
- Voice waveform visualization — daemon has no audio surface yet
- Avatar / portrait rendering — gimmick, no information value
- Multi-user, auth, sessions, cookies — localhost-only
- Mobile responsive (Phase 1) — operator uses laptop; phone view is
  Phase 2 if/when SSH-tunnel or Tailscale demand surfaces
- Light mode — JARVIS aesthetic is dark, period
- Customizable layout, themes, settings page — single hardcoded layout
- UI-driven writes (trigger agent, approve PR, edit memory) — read-only
  Phase 1; write actions stay in CLI + voice
- SSE / WebSocket — see §11 critic finding, replaced by 3s poll
- Charts / graphs / time-series — text + single progress bar suffice
- Web fonts, icon libraries, CSS frameworks — system fonts + raw CSS
- TypeScript, build pipeline, bundler — vanilla JS, no build
- Service worker, offline mode, PWA — localhost-only, irrelevant
- Dark/light toggle, accessibility audit beyond `prefers-reduced-motion`
  + sufficient contrast — single operator, no a11y customer

## 10. Scaffolding deferred — why

Two unknowns block useful scaffolding:

- **Memory M2** (`docs/specs/2026-06-09-memory-m2-minimal.md`) —
  table shapes for `contacts` / `projects` / `decisions` are still
  being implemented. Hardcoding to a stale schema means rewriting
  the `memory.*` block in `/api/state` later.
- **Self-improvement** (tier-1) — may add new state surfaces
  (skill registry, retro log) that the dashboard should expose. Better
  to design the `Snapshot()` shape once both are known.

**Reopen-trigger**: when both memory + self-improvement land on main,
this spec moves to `status: ready` and Task 1 dispatches.

## 11. Adversarial review (inline critic, single-author acknowledged)

The operator runs solo on this repo; no independent reviewer subagent
is required for personal-use specs. Critic pass below catches what an
independent reviewer would flag. Findings are folded into §§4, 6, 7, 9.

| # | Severity | Finding                                                                                                                                                  | Resolution                                                                                              |
|---|----------|----------------------------------------------------------------------------------------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------|
| 1 | CRITICAL | "JARVIS without 3D" risks disappointing operator who wanted cool factor                                                                                  | Premise-stress-test §2 already kills holograms; dark+cyan+pulse delivers 80% of the aesthetic at 5% of cost. Accept residual disappointment. |
| 2 | HIGH     | SSE from daemon = first HTTP surface in daemon = mission creep                                                                                           | Replaced SSE with 3s poll (§4, §6). Server is still new but minimal — single endpoint, no streaming.    |
| 3 | HIGH     | 4-5 API endpoints bloat backend surface                                                                                                                  | Collapsed to single `/api/state` (§4).                                                                  |
| 4 | HIGH     | Pulse animation costs CPU on idle laptop                                                                                                                 | Single 3s CSS keyframe, paused on `visibilitychange` + `prefers-reduced-motion` (§3).                   |
| 5 | MED      | Personal-use weekly-open → 1 week of work = bad ROI vs. voice / Memory / self-build                                                                      | Build order capped at 5 tasks (§8), each ~1-2h. Total ≤ 1 day, not 1 week.                              |
| 6 | MED      | Phone view requested someday → SSH tunnel / Tailscale solves without responsive CSS                                                                       | §9 explicitly defers mobile to Phase 2 with reopen-trigger.                                             |
| 7 | MED      | Localhost-only assumes operator never wants to view from couch / phone                                                                                   | Tailscale + 127.0.0.1 bind covers the rare case without code change (tailscale routes to loopback).     |
| 8 | LOW      | `embed.FS` reload requires daemon restart during dev                                                                                                     | Acceptable; single operator can `make run` in a loop. Could add `--web-dev-dir` flag later if painful. |
| 9 | LOW      | No CSRF / origin checks on `/api/state`                                                                                                                  | Read-only endpoint on loopback; CSRF irrelevant Phase 1. Reopen when UI-driven writes land.            |

**Critic verdict — REVISE**:
- Adopt single-endpoint poll (done, §4)
- Cap build order at 5 tasks (done, §8)
- Default daemon flag OFF (done, §7)
- Explicit ROI bound: ≤ 1 day of operator time (added to §8)

**Critic-driven further scope cut beyond original brief**:
- Original brief named SSE; critic cut it. Saved ~80 LoC + reconnect
  logic + browser tab-idle handling.
- Original brief named 4 endpoints; critic collapsed to 1. Saved ~120
  LoC of handler code + 4 client fetches.
- Original brief named separate `/dashboard` HTML route; kept, but
  noted that asset count = 3 files (html/css/js), nothing more.
- **No further cuts identified**. The minimal-dashboard branch is at
  irreducible scope for the stated goal.

## 12. Acceptance criteria
