## Headline

**v3.1's rename is non-atomic and the parity test it claims will catch the leakage is unrunnable as specified.** "Chamber" survives in 131 distinct lines, "sigil" in 60+, "flourish" in 23. The §16.7 parity-grep rule excludes BOTH §3.5/§4.3 (where the new names are *defined* and inevitably reference the old) AND §13 wireframes (which are still using `chamber` everywhere). If `make check-spec-parity` is run today against this spec it FAILS — the test the v3.1 fold added would block the v3.1 spec it shipped with. That is the central regression.

Second-order: v3.1 added decision rows #110-#118 and §0.1/§0.2/§2.7/§13.14 but did not propagate the renames out from those new sections into §1, §2-§12, §13.1-§13.13, or §16-§17.2 prose. The spec is in two voices.

### B. New blind spots (i18n / multi-user / peripherals / power / system)

23. §1, §11.3, all wireframes: 🟡 NEW-GAP: **i18n footprint is zero.** Zero hits for `NSLocalizedString` / `i18n` / `locale` / `plural`. Every user-facing string in the spec (placeholder "Ask Leah anything…", VoiceOver labels, "Good morning, Tri.", "Daemon offline. Click to restart Leah.", wizard copy) is hardcoded English. v1 ship may be English-only but the spec should declare that explicitly + commit (or defer) NSLocalizedString. Fix: add §1 scope footer "v1 ships English-only; all user-facing strings flow through NSLocalizedString to enable post-v1 localization without UI surgery."
24. §11, §3.3 Dynamic Type reflow: 🟡 NEW-GAP: **RTL layout** never mentioned. Arabic/Hebrew operators would see mirrored chrome, but ambient HUD anchor logic, pin-divider direction, mark-on-left vs state-on-right are all LTR-baked. Fix: explicit "RTL: ambient HUD mirrors; mark on right, state on left; pin chevrons mirror" or "RTL out of scope for v1, will require §7.1 redraw".
25. §3.3:169 Tiempos / New York fallback: 🟡 NEW-GAP: CJK / Cyrillic fallback now mentioned (good — v3.1 added). But the parity-rule "Tiempos italic" forbidden phrase is the *English* string; an i18n'd build with "今日" header would not match the grep. Acceptable for v1 English-only ship but flag it.
26. §6.7 onboarding + §8.6 wizard: 🟡 NEW-GAP: **wizard telemetry / opt-in/out events are unspecified.** "telemetry" appears 22 times in the spec but always in non-onboarding contexts. Spec does not say whether the wizard logs "step 3 mic granted/denied/skipped" or whether there is an opt-out toggle in the wizard. Fix: add §8.6 row "Wizard step 5 — privacy: opt-in checkbox for anonymized crash + diagnostic events (default OFF); per HIG and v3.1 brand-voice canon"; or add §8.6 explicit "no telemetry in wizard; lazy-prompt later".
27. §6 daemon-down + §11.5 daemon-down: 🟡 NEW-GAP: **HUD process crashes mid-stream — recovery story missing.** §11.5 has "Daemon down → menubar pulses red", but if the HUD UI process (separate from daemon) crashes mid-stream-response, what happens? `crash` appears 1× and refers to screen-recording end. Fix: add §6.6 row "HUD UI crash recovery: launchd respawns under com.leah.hud; daemon replays last-frame buffer to restore in-progress stream; max 2 respawns/min before backoff".
28. §6, §11, §18: 🟡 NEW-GAP: **Multi-user macOS — Fast User Switching.** Zero hits. Two users on the same Mac: does each get their own daemon (XPC per-user is standard, but unstated)? Does the global hotkey conflict if both are logged in via Fast User Switch? Fix: add §6.1 row "Daemon runs per-user via launchd `~/Library/LaunchAgents/com.leah.daemon.plist`; Fast User Switch suspends background user's daemon via `NSWorkspaceSessionDidResignActiveNotification`".
29. §17.1 explicitly-not + §17.2: 🟡 NEW-GAP: **iCloud Drive sync of pinned-widgets.json / conversation history is unspecified.** §17.1:2519-2520 lists "Cloud sync / account creation" + "iCloud Keychain" under "not in v1" — but §10.3 says `pinned-widgets.json` lives in Application Support. If a user has Application Support symlinked to iCloud (some power users do), state survives across devices accidentally. Fix: explicitly say "Pinned-widgets file is per-machine; not iCloud-eligible. Symlinks ignored / file is opened with `NSFileProtectionComplete` to prevent iCloud sync."
30. §6.1, §6.6: 🟡 NEW-GAP: **External keyboard vs MacBook keyboard hotkey behavior** — §6.1:444 *does* address Fn-PTT differences for external keyboards (right-⌘ fallback). But the ⌥Space global hotkey itself — does it work over Bluetooth Magic Keyboard with input-monitoring permission? Apple's input-monitoring is granted per-keyboard layout but not per-device-instance; worth a sentence. Fix: §6.1 footer "⌥Space registers via `RegisterEventHotKey`; works identically on built-in and Bluetooth Magic Keyboard. Sticky-Keys ON: chord still fires on Option+Space release because RegisterEventHotKey filters before Sticky-Keys."
31. §6.6, §11.2: 🟡 NEW-GAP: **AirPods vs built-in mic — wake-word reliability.** Wake-word is opt-in and acknowledged as low-quality (default OFF), but no spec on input-source selection. If AirPods are the system default and operator removes them mid-session, does wake-word re-bind to built-in mic? Fix: §6.6 row "Audio-input route changes (`AVAudioSession routeChange notification`) → daemon re-binds wake-word + transcription input. AirPods battery <10% → notify operator; auto-fall-back to built-in mic when AirPods disconnect."
32. §10.2 widget refresh, §11.5 offline: 🟡 NEW-GAP: **VPN / corporate proxy + TTS / LLM API calls.** Spec assumes direct HTTPS to LLM provider. Corporate operator behind WPAD proxy will see widget refresh fail and TTS fall silent (Apple's AVSpeechSynthesizer is on-device so that's fine, but third-party TTS requires net). Fix: §11.5 row "VPN / system proxy: HTTPS requests inherit `URLSessionConfiguration.default` proxy; offline-banner copy includes 'Check VPN' affordance if `kCFNetworkProxiesHTTPEnable`."
33. §4.2 ambient HUD agenda row, §10.1 calendar widget: 🟡 NEW-GAP: **Timezone / DST.** Ambient HUD "weather of the day's agenda" and calendar widgets need a timezone source. Zero hits for `timezone`/`DST`. Operator who travels to Tokyo will see meetings drift if widget renders in old TZ. Fix: §10.1 footer "Time-of-day rendering uses `Calendar.current.timeZone` (system TZ); refreshes on `NSSystemTimeZoneDidChangeNotification`."
34. §11, §17.2: 🟡 NEW-GAP: **macOS Low Data Mode.** §11.5 has "Memory pressure" and "System idle ≥ 10 min animation halt" but no Low-Data-Mode entry. `low.data` has 3 hits, all in tangential contexts. Fix: §11.5 row "Low Data Mode (`URLSessionConfiguration.allowsConstrainedNetworkAccess = false`): widget auto-refresh extends TTL ×4; quick-spawn chips disabled."
35. §11.2 reduced motion, §11.5 system idle: 🟡 NEW-GAP: **Low Power Mode** does not appear explicitly. Wake-word is off by default so that mitigation is moot, but background widget polling, listening pulse, thinking arc should likely throttle under Low Power Mode. Fix: §11.5 row "Low Power Mode (`ProcessInfo.processInfo.isLowPowerModeEnabled`): widget refresh interval ×3; decorative animations swap to dur-instant; speaking waveform suppressed."
36. §6.3 idle ≥ 5 min, §10.2 widget refresh: 🟡 NEW-GAP: **Sleep/wake state for in-flight widget refresh queue.** Zero hits for sleep/wake notifications. After `NSWorkspaceDidWake`, are queued refreshes flushed in a thundering herd? Fix: §10.2 row "On `NSWorkspaceDidWake`: pinned-widget refreshes are jittered ±5 s over a 30 s window to avoid thundering herd against rate-limited APIs (e.g. GitHub)."
37. §6.6 focus panel, §10.0 ambient HUD: 🟡 NEW-GAP: **Two-finger pinch zoom on trackpad.** macOS Accessibility Zoom is system-wide and §11.4 covers Dynamic Type reflow, but in-app pinch-to-zoom on widget content (chart tiles, map citation card) is unspecified. Fix: §10.0 row "Tiles ignore pinch gestures; pinch over a focus panel falls through to system Zoom; operator can opt in per-tile via long-press → 'Zoom this widget' (post-v1)."
38. §6.6, §11.5: 🟡 NEW-GAP: **Force-quit recovery.** User force-quits Leah from Activity Monitor. Daemon dies without graceful shutdown. On next launch: is `pinned-widgets.json` write-atomic? Is conversation history left in inconsistent state? `force.quit` has 0 hits. Fix: §10.3 footer "Pinned-widgets writes via `Data.write(.atomic)`; conversation-history journal uses WAL — daemon crash mid-write leaves last-good state on next launch."
39. §17.2, §16.9 perf tests: 🟡 NEW-GAP: **macOS major-version compatibility testing.** §17.2 lists target macOS as Sequoia (?) — `macOS NN` has 18 hits but no compat matrix. Spec does not say "test on macOS 14 + 15 + 16; fail on 13 or earlier". Fix: §16.9 footer "Min target = macOS 14 (Sonoma); CI runs `xcrun simctl` matrix on 14, 15, 16-beta; entitlements file pins `LSMinimumSystemVersion = 14.0`."
40. §13.14:2035 hero composition, §10.0 grain texture: 🟡 NEW-GAP: **Killer screenshot under reduced-transparency / increase-contrast / dark-mode-mismatch.** §13.14 hero spec is dark + glass + ivory. What does the marketing hero look like when the operator has Reduce Transparency ON? Specs the screenshot as binding but no a11y-degraded variant exists. Fix: §13.14 footer "Hero composition rendered in spec'd surface only; degraded-state heroes (reduce-transparency, increase-contrast, light-mode) live in /marketing/hero-variants/ — not the killer-screenshot canonical."
