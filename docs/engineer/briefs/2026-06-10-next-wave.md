# Brief — Next wave priority list (2026-06-10)

Status: ready (Wave 10 candidate set)
Source: roadmap-planner scan after Wave 9 wrap (19 PRs #44–#62 merged 2026-06-09; first-launch-connect shipped as #47).

## Decision rationale

UX first. Wave 9 landed the gmail + gcal adapters and the `leah connect`
first-launch flow, but the morning brief (`internal/brief/brief.go`) still
renders without unread mail or today's events — the single visible feature
the operator sees every day. Wiring those two `ListUnread` / `ListToday`
calls into `Gather` is the highest-leverage UX delta available with the
surface that already exists, and it is the tie-in both adapter specs cited
as their reason for existing. That is W10-1.

After UX, the next priority is the durability gaps the connect flow opened:
OAuth refresh-token rotation (W10-2) and `leah disconnect` (W10-3) were both
called out as "deferred" / "out of scope" in the gmail + gcal briefs, and
without them the first run of Leah goes silently stale on day-N and has no
clean exit. Operator-attestation question pool centralization (W10-4) is
the long-term cleanup that pays back as more adapters land. Audit retention
(W10-5) follows the dailyRotator landing (#60) — rotation without retention
just defers the disk-full problem. Self-learn ↔ operator-model feedback
(W10-6) closes the loop the spec base implies but no code yet wires. CI
matrix live-gh (#26) is the lone open issue; ranked last because it gates
quality of an already-shipped surface and operator-model + brief enrichment
deliver more day-1 value.

## Candidates (ranked)

### W10-1: Wire gmail + gcal into morning brief

- **Goal:** `internal/brief/Gather` calls `gmail.ListUnread` + `gcal.ListToday` and renders both sections in `Render`; missing/denied auth degrades gracefully (mirrors the existing regatta soft-fail pattern at `brief.go:62`).
- **Files touched:** `internal/brief/brief.go`, `internal/brief/brief_test.go`, `cmd/leah-daemon/brief.go` (constructor wiring), `cmd/leah-daemon/attestation.go` (share `Attestor` across both adapters per gcal-adapter §4).
- **Spec needed:** No (gmail-adapter.md §"Future wiring" + gcal-adapter.md §4 are the canonical contracts).
- **Risk:** Med — first place adapter token IO meets the daemon; ordering of attestation-before-token-load must be preserved or a denial leaks the bearer.
- **Estimated PR size:** M (≈250 LOC including tests).
- **Unblocks:** W10-2 (refresh path now has a real caller), W10-4 (centralization triggered by second consumer of the question pool).
- **Test plan:**
  - Hermetic `Gather` test with fake `gmail.Transport` returning 3 unread ids → renders "## Unread mail" section with count.
  - Hermetic `Gather` test with fake `gcal.Transport` returning 2 events → renders "## Today's calendar" section.
  - `ErrAttestationDenied` path: section renders "(attestation denied — run `leah connect`)" and other sections still populate.
  - Missing token file (`ErrAuthRequired`): section renders "(not connected — run `leah connect gmail`)".
  - Brief snapshot test (`internal/brief/brief_test.go` existing fixture) updated to include both new sections in canonical order.

### W10-2: OAuth refresh-token rotation

- **Goal:** Daemon-side `TokenSource` that detects 401 from gmail/gcal RPCs, exchanges the stored `refresh_token` for a new access token, rewrites the token file at `0600`, retries once. Attestation re-runs on rotation per gcal-adapter §3 step 5 ("silent refresh would bypass the audit row").
- **Files touched:** `internal/connect/refresh.go` (new), `internal/connect/refresh_test.go` (new), `cmd/leah-daemon/main.go` (cron tick to proactively refresh tokens approaching expiry — coarse hourly check is enough).
- **Spec needed:** Yes — `docs/engineer/specs/2026-06-10-token-refresh.md` (short, ≈80 lines): refresh trigger conditions, audit-row shape (`Kind: "refresh_gmail" | "refresh_gcal"`), 401-retry contract, retry budget.
- **Risk:** Med — silent refresh that skips attestation is the threat model called out twice across the adapter specs; the test that fails the refresh if `Attestor.Attest` is not called is load-bearing.
- **Estimated PR size:** M (≈350 LOC; spec is a separate small PR).
- **Unblocks:** Long-running daemon sessions (currently the first 401 ends the integration silently).
- **Test plan:**
  - Refresh on 401: httptest stand-in returns 401 once → refresh call → second RPC succeeds.
  - Refresh without attestation: failing `Attestor` short-circuits before token file is rewritten; old token file bytes unchanged on disk.
  - Refresh writes 0600: post-rewrite `os.Stat` mode bits asserted (mirrors `connect_test.go` 0600 pin).
  - Expiry-window proactive refresh: token `expires_at - 5m` triggers refresh in the next hourly tick.
  - Refresh-failure backoff: 3 consecutive failures stop the loop and surface `ErrAuthRequired` to callers instead of hot-looping Google's auth endpoint.

### W10-3: `leah disconnect <integration>`

- **Goal:** Inverse of `leah connect`. Revokes the OAuth token at the provider, deletes `<sd>/secrets/<name>-token.json`, appends a `disconnect_<name>` audit row. Re-asserts 0600 doesn't matter on delete, but the audit row matters for the operator-consent timeline.
- **Files touched:** `cmd/leah/disconnect.go` (new), `cmd/leah/disconnect_test.go` (new), `internal/connect/registry.go` (add `Revoke(ctx, token) error` to the `Provider` interface), `internal/connect/{gmail,gcal}.go` (implement revoke).
- **Spec needed:** No (mirror-of-connect; one paragraph in the PR body suffices).
- **Risk:** Low — pure file delete + one HTTP POST; no token-leak surface beyond what `connect` already handles.
- **Estimated PR size:** S (≈150 LOC).
- **Unblocks:** Clean exit for operators uninstalling Leah; pre-req for W10-7 (multi-account future).
- **Test plan:**
  - Happy path: token file present → revoke HTTP POST hit → file deleted → audit row appended.
  - Idempotent: missing token file → exit 0 with "(not connected)" message; no audit row (nothing to attest to).
  - Revoke network failure: file is still deleted (operator-intent preserved) and audit row marks `revoke_failed=true` so the operator can manually revoke.
  - Unknown integration: `exit 2` matching connect-side error convention.

### W10-4: Centralize operator-attestation question pool

- **Goal:** Move attestation question selection out of `dispatcher/selfbuild.go` into a new `internal/attestation/` package that owns `prompts/attestations/*.txt`, exposes `Pick(ctx, scope) (string, error)`, and is shared by dispatcher + gmail-adapter + gcal-adapter + (future) disconnect. Selfbuild keeps its current behavior via the new API; question pool is now scope-segmented (`selfbuild.txt`, `gmail.txt`, `gcal.txt`).
- **Files touched:** `internal/attestation/{attestation.go,attestation_test.go}` (new), `internal/dispatcher/selfbuild.go` (replace `pickAttestationQuestion` with package call), `prompts/self-build-attestations.txt` → `prompts/attestations/selfbuild.txt`, `prompts/attestations/{gmail,gcal}.txt` (new short pools).
- **Spec needed:** No (refactor — preserve selfbuild semantics; document the new contract in the package godoc).
- **Risk:** Low-Med — selfbuild tests pin lastQuestion behavior; the rename has to keep them green.
- **Estimated PR size:** M (≈200 LOC net; mostly moves).
- **Unblocks:** W10-2 (refresh attestation uses the same picker), W10-3 (disconnect attestation), future adapter wiring across more providers.
- **Test plan:**
  - Pick by scope returns only questions from that pool's file.
  - Empty pool returns a sentinel error; dispatcher fail-open behavior preserved.
  - Selfbuild test suite stays green with no behavior change.
  - Race: 8 parallel `Pick` calls — no shared mutable state.

### W10-5: Audit log retention / rotation policy

- **Goal:** `obs.dailyRotator` (#60) rotates by day; nothing prunes. Cap at last-N days (default 30, env `LEAH_AUDIT_RETENTION_DAYS`); gzip rotated files older than 7 days. One daemon tick handles both.
- **Files touched:** `internal/obs/retention.go` (new), `internal/obs/retention_test.go` (new), `cmd/leah-daemon/obs.go` (daily cron call).
- **Spec needed:** Yes — `docs/engineer/specs/2026-06-10-audit-retention.md` (≈60 lines): default window, gzip threshold, what triggers prune (cron vs write-time), how `costview.Aggregate` reads gzipped tails.
- **Risk:** Med — costview + brief both read `audit.jsonl`; their readers need to transparently consume `.jsonl.gz` rotated files, otherwise yesterday's spend silently zeroes on day-8.
- **Estimated PR size:** M (≈300 LOC including reader gzip-transparency change).
- **Unblocks:** Multi-week operator sessions without manual disk-cleanup.
- **Test plan:**
  - 31-day fixture: oldest file deleted, count = 30.
  - 8-day fixture: files older than 7d are `.jsonl.gz`; today's file is plain.
  - `costview.Aggregate` over a 14-day window reads gz + plain transparently and total matches plain-only baseline.
  - `brief.ScanYesterday` over a gzipped 2-day-old file returns the same counts as the plain version (round-trip pin).
  - `LEAH_AUDIT_RETENTION_DAYS=0` disables prune (escape hatch).

### W10-6: Self-learn ↔ operator-model feedback loop

- **Goal:** `selflearn.Resolver` outcomes (ship_outcome ok/failed/dangling) feed `operatormodel.Profile.Update`. Today they live in disjoint packages with no edge between them; recommendations cannot reflect what just shipped or just regressed.
- **Files touched:** `internal/operatormodel/feedback.go` (new — accepts a typed `selflearn.Outcome` rather than importing the package, to keep the dependency arrow one-way), `internal/selflearn/resolver.go` (emit outcomes via an injected callback rather than only writing to disk), `cmd/leah-daemon/main.go` (wire the callback at daemon-boot).
- **Spec needed:** Yes — `docs/engineer/specs/2026-06-10-selflearn-operatormodel-feedback.md` (≈100 lines): the import-arrow direction (selflearn callback → operatormodel observer, NEVER operatormodel → selflearn), the outcome event shape, how `Profile.Ready` is affected by feedback velocity.
- **Risk:** Med-High — import cycle risk is real; the callback indirection is load-bearing. Spec must pin direction before code.
- **Estimated PR size:** L (≈500 LOC; spec is a separate small PR).
- **Unblocks:** Recommendations that actually adapt to recent ship outcomes (currently they're frozen on history).
- **Test plan:**
  - Outcome `dangling` after 7d (matches PR #44 semantics) → `Profile.Update` sees a `kind=ship_dangling` observation.
  - No outcome → `Profile` unchanged (negative-test for spurious updates).
  - Import-graph CI gate: `go list -f '{{.Imports}}' ./internal/operatormodel | grep selflearn` returns empty (one-way dependency pinned).
  - Recommend-after-feedback: a recent `ship_failed` outcome lowers the score of the same recommendation kind for the next hour.
  - Stress: 100 outcomes in 1s do not block the resolver (callback is non-blocking; queue-with-drop on overflow).

### W10-7: CI matrix live-gh (closes #26)

- **Goal:** Add a `live-gh` job to the CI matrix that exercises `ship.Run` retry against a real `gh` binary with a stubbed remote, gated by a repo secret. Matches the Wave 8 followup the issue tracks.
- **Files touched:** `.github/workflows/check.yml`, `internal/dispatcher/ship_test.go` (add a build-tag-gated `TestShipRunLive`), `Makefile` (`check-live-gh` target).
- **Spec needed:** No (CI plumbing; PR body cites #26).
- **Risk:** Low — gated by env so it can't break offline contributors; matches existing `check-no-bare-sleep` pattern from PR #35.
- **Estimated PR size:** S (≈120 LOC).
- **Unblocks:** Closes the only open issue; clears the followup backlog.
- **Test plan:**
  - Live job runs and passes on a PR from the repo owner (where the secret is available).
  - Job is `skip`ed (not `fail`ed) on PRs from forks (secret not exposed).
  - `make check-live-gh` runs locally when `LEAH_LIVE_GH=1` is set and a `gh` binary is present.
  - Failure: retry budget exceeded → test reports retry count + final error (not a hang).
