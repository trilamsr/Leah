# HUD UI — Leah operator overlay

Status: spec (W34–W37 design lock)
Owner: trilamsr
Surface: `cmd/leah-hud/`, `internal/hud/`, `internal/hud/static/`

## 1. Goal

A glanceable operator-overlay UI on macOS. Not a chat-app, not a full-screen
takeover — a frameless, transparent, optionally always-on-top, optionally
edge-docked surface. The operator dismisses with Esc and summons with a
global hotkey. The overlay shows ambient telemetry at rest and expands to a
focus panel when the operator queries Leah by voice or hotkey. The aesthetic
is "operator-AI overlay": transparent panels, radial activity meters,
ambient telemetry, glanceable status surfaces, animated transitions. The
look is ours; no franchise IP is referenced.

The HUD is the first visual surface Leah owns. Voice (W11–W14) is the input
modality the HUD complements: when the operator speaks, the HUD reflects
listening state; when Leah replies, the focus panel shows the spoken text
plus citations. When idle, the ambient surface earns its pixels by carrying
weather, calendar-next, market ticker, and a rotating headline — content the
operator otherwise context-switches to a browser for.

## 2. Mental model — two surfaces, one process

Two surfaces, drawn by the same daemon UI thread:

| Surface | Size | Opacity | Trigger | Dismiss |
| --- | --- | --- | --- | --- |
| **Ambient HUD** | ~320×600 | semi-transparent (0.6) | always-on by default | operator toggle |
| **Focus panel** | ~720×640 | mostly opaque (0.92) | voice query OR hotkey | Esc or 30s idle |

Both surfaces are part of the same process (`leah-hud`), drawn by the same
UI thread. They are NOT two windows in two binaries. The ambient HUD is the
default state; the focus panel is a state transition, not a separate window.
The daemon (`leah`) streams telemetry into the HUD process via gRPC; the HUD
is a thin presentation layer over daemon state, not a re-implementation of
Leah's reasoner or feeds.

State machine: `hidden ↔ ambient ↔ focus`. Transitions:

- `hidden → ambient` — operator hotkey, or auto-show on login (operator-config)
- `ambient → focus` — voice query detected, or hotkey-summon
- `focus → ambient` — operator finishes interaction OR 30s idle
- `* → hidden` — Esc, screen-recording detected, or DND/Focus mode entered

Single-surface invariant: only one of {ambient, focus, hidden} is active.
No overlap. No "ambient peeks through focus." The focus panel replaces the
ambient panel in-place (same window, resized + restyled) — operator-flow
stays continuous.

## 3. Tech choice — Wails (Go + Web)

Five options were considered. Decision: **Wails**.

| Option | Pros | Cons | Verdict |
| --- | --- | --- | --- |
| A) Tauri (Rust+Web) | Small binary, web aesthetic | Adds Rust toolchain; needs Go-sidecar bridge | **Reject** — toolchain bloat |
| **B) Wails (Go+Web)** | Native window, pure-Go back, web aesthetic | Smaller community than Electron | **Accept** |
| C) Native SwiftUI | Best macOS look | Swift toolchain; Go-bridge complexity; Linux-future-blocked | **Reject** — toolchain + future-blocked |
| D) Fyne / Gio (pure Go) | Pure Go | HUD aesthetic uphill; limited polish | **Reject** — UX cost too high |
| E) Web dashboard + WKWebView wrapper | Reuses `internal/web/` | Cocoa NSWindow gymnastics; transparency fragile | **Reject** — fragility |

Reasons Wails wins, applying `CLAUDE.md` priority UX > performance > long-term:

- **UX**: CSS-level control gives the transparent-panel + radial-meter
  aesthetic at low effort. SwiftUI matches; Fyne/Gio doesn't.
- **Performance**: Native window, single binary, no Electron-bundle weight.
  Cold-start budget < 400ms; idle CPU < 1% of one core. Tauri matches;
  Electron wouldn't.
- **Long-term**: Pure-Go stack matches the rest of the codebase. No Rust
  toolchain (Tauri), no Swift toolchain (SwiftUI), no Cocoa hand-rolling
  (option E). The HUD ships in the same `go build` flow as `leah` itself.

The decision is reversible. If Wails proves a dead-end (e.g. webview
transparency breaks on a future macOS), option C (SwiftUI) is the fallback;
the gRPC contract between daemon and HUD is the stable seam.

## 4. Surface — packages, binaries, IPC

```
cmd/leah-hud/main.go            Wails entrypoint; initializes window + gRPC client
internal/hud/                   UI state machine + IPC to daemon
internal/hud/state.go           ambient/focus/hidden state machine
internal/hud/grpc.go            gRPC client subscribing to daemon telemetry stream
internal/hud/hotkey.go          macOS global-shortcut registration (Wails API)
internal/hud/screencast.go      macOS screen-recording detection (auto-hide)
internal/hud/static/            HTML/CSS/JS — mirror of internal/web/static/
internal/hud/static/index.html  ambient + focus panel templates
internal/hud/static/hud.css     aesthetic spec realized as CSS
internal/hud/static/hud.js      DOM bindings + animation logic
```

The daemon exposes a gRPC stream `Telemetry.Subscribe` that the HUD
subscribes to on launch. Stream payload:

```protobuf
message TelemetryFrame {
  google.protobuf.Timestamp ts = 1;
  WeatherSummary weather = 2;
  MarketPulse market = 3;
  NewsDigest news = 4;
  CalendarNext calendar = 5;
  ListeningState listening = 6;   // mic on/off, wake-armed, in-utterance
  ThinkingState thinking = 7;     // reasoner in-flight, last call duration
}
```

Frames are pushed at most every 500ms (rate-limited daemon-side); the HUD
re-renders only diffs. Two-way RPC: HUD pushes operator events (hotkey
dismiss, panel-focus-change) back to the daemon via the same stream.

## 5. Aesthetic spec — CSS-level

Values are the canonical defaults; operator-config (W37) overrides accent
color and opacity.

| Token | Ambient | Focus |
| --- | --- | --- |
| background | `rgba(8, 12, 20, 0.6)` | `rgba(8, 12, 20, 0.92)` |
| border | `1px solid rgba(255,255,255,0.08)` | `1px solid rgba(255,255,255,0.12)` |
| border-radius | `12px` | `12px` |
| backdrop-filter | `blur(18px) saturate(140%)` | `blur(24px) saturate(160%)` |
| accent | `#5af2ff` (cyan) | `#5af2ff` |
| body font | system (SF Pro on Mac) | system |
| telemetry font | monospace (SF Mono) | monospace |
| panel padding | `16px` | `24px` |

Radial activity meters:

- CPU / memory ring — shown only when daemon load > 25% (no "decorative"
  visualization of idle hardware)
- Leah-thinking ring — pulses while a reasoner call is in flight
- Voice-listening ring — pulses at ~1Hz while mic is hot, faster while
  wake-armed

Animations:

- 200ms ease-out on appear / dismiss
- 400ms cross-fade on ambient ↔ focus transition
- Subtle 1Hz pulse on listening-state (opacity 0.7 → 1.0)
- No animations exceed 600ms — operator attention is the budget

All text passes WCAG AA contrast against the transparent backgrounds at
both the ambient and focus opacity tiers, tested against a black AND a
white desktop background.

## 6. Information density per panel

**Ambient HUD** (no scrolling, ≤7 data rows):

1. Time + date (1 row, large)
2. Location + weather (1 row: condition icon + temp + high/low)
3. Calendar next (1 row: time + title, truncated)
4. Top headline (1 row, rotates every 20s)
5. Market ticker (1 row: 2-3 tracked symbols + % change)
6. Listening / thinking ring (anchored bottom)
7. Reserved for one operator-pinned widget (W37)

**Focus panel** (scrollable, multi-section):

- Response section (top, ~60% height): Leah's text reply, rendered
  markdown. Streaming-friendly — incremental render as text arrives.
- Sources section: bulleted citations with source-name + URL chip
- Suggestions section: 0–3 follow-up prompts as clickable chips
- Dismiss affordance: Esc hint + close icon top-right

## 7. Privacy

HUD content is operator-private. The HUD process has NO outbound network
beyond the gRPC connection to the local daemon. The HUD never ships
operator-visible content to any remote reasoner; the daemon is responsible
for redaction before any cloud call.

Sensitive-content blocklist:

- Default blocklist words: password, banking, ssn, mfa, otp, recovery,
  secret, token. Operator-configurable (W37).
- When a blocklist match is detected in a panel's text, the matching span
  is rendered with `filter: blur(8px)` until the operator hovers (mouse
  reveal) or speaks "show it" (voice reveal).

Screen-recording auto-hide:

- macOS exposes `CGDisplayStream` and screen-recording-permission APIs;
  the HUD polls the screen-recording-active flag every 2s.
- When screen-recording is detected, the HUD transitions to `hidden`. A
  small system-tray indicator stays visible so the operator knows Leah is
  alive; the panels disappear.
- Operator can override per-session ("show during recording") but the
  default is hide-fast.

DND / Focus modes:

- macOS Focus modes are readable via `NSUserDefaults` / Notification
  Center APIs. When Focus is active, the HUD visual nudges quiet:
  - No pulse animations
  - No headline rotation
  - Ambient panel opacity drops to 0.3
  - Focus panel still works on explicit operator hotkey (Focus isn't a
    hard mute, it's a "stop nudging me")

## 8. Operator-attestation

First HUD launch is operator-attested per `internal/attestation` (PR #67):

- Attestation prompts request, in order: global-hotkey grant, screen-
  recording-detection grant, optional Focus-mode read grant.
- Each grant is independent. The HUD degrades gracefully if a grant is
  denied (no hotkey → tray-icon-summon only; no recording-detect → no
  auto-hide).
- Attestation tokens stored under `~/.leah-state/attestation/hud-*.json`
  mode 0600, same shape as gmail/gcal/macos.

The HUD respects existing daemon-level attestation: if the daemon hasn't
been operator-attested at all, the HUD launches in a "tray-only, no
panels" mode and prompts the operator to complete daemon attestation
first.

## 9. Test plan

Failing-test-first per `CLAUDE.md`. Tests live in `internal/hud/`:

- **State-machine tests** (`state_test.go`): table-driven transitions for
  `ambient ↔ focus ↔ hidden`. Verifies single-surface invariant, idle
  timeout, screen-recording auto-hide.
- **Telemetry diff tests** (`grpc_test.go`): given a stream of
  `TelemetryFrame`, verify the HUD only emits DOM updates for changed
  fields. Coverage gate: 100% of diff paths.
- **HTML snapshot tests** (`render_test.go`): headless render of the
  ambient + focus templates against fixture data; golden HTML stored
  under `internal/hud/testdata/`. No real window opened.
- **Privacy redaction tests** (`privacy_test.go`): blocklist match → DOM
  contains `<span class="blur">…</span>`. Tested across all panel slots.
- **Manual smoke test gate** (operator-side, NOT CI): documented in
  `docs/engineer/runbooks/hud-smoke.md` (out of scope for this spec).
  Covers: real-window appearance, animation smoothness, hotkey grant
  flow, screen-recording auto-hide, DND-mode quieting.

CI never opens a real window. The HUD's DOM is renderable as a string;
that string is what we test. Visual regressions are caught operator-side,
not in CI — accepted trade-off.

## 10. Out of scope (MVP)

- Multi-monitor placement memory (defer to post-W37)
- Gesture controls (trackpad swipes to dismiss / summon)
- Custom themes beyond accent-color override
- Animated avatar / face / mascot — explicit non-goal
- Gamification surfaces (streaks, XP, achievements) — explicit non-goal
- Windows / Linux ports — Mac-only in MVP; the gRPC seam keeps portability
  cheap later
- Mobile companion app — defer

## 11. Risks + open questions

- **Wails transparency fragility on macOS upgrades.** Mitigation: pin
  Wails version; smoke-test on each macOS minor release. Fallback: option
  C (SwiftUI) behind the same gRPC seam.
- **Hotkey conflicts with operator tools.** Mitigation: operator-config
  hotkey at first-run; sensible default (e.g. `⌘⇧L`) but never assumed.
- **Webview cold-start latency.** Budget: < 400ms. If exceeded, the HUD
  daemon preloads the webview on login (out of process from `leah`) so
  the first hotkey-summon is instant.
- **Accessibility — VoiceOver compatibility.** Open question deferred to
  W37 operator-config wave. Track at follow-up issue.
